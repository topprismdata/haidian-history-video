## QA 流程（v2，2026-09-28 增补，每支渲染后必跑）

1. **全局**：ffprobe 时长 vs 预期(帧数/30)±0.5s；volumedetect max>-6dB；音轨存在
2. **逐页终态帧**：`qa_frames2.py <mp4>` 抽每页 late 帧（音频末-0.6s，全元素已入场）+ mid 帧，PIL 烧 PXX/时间戳红标签（防视觉模型张冠李戴）
   > 2026-10-02 E12 反向审查建议：E8 起出场锚点=音频末−0.5s，−0.6s 会落在入场未满窗口，late 帧口径应统一为**音频末−0.2s**（E12 反向走查即用此值）
3. **逐页视觉核验**：一次一页，问句附该页预期元素清单，逐项 PASS/FAIL
4. FAIL→修源码→**重渲染后**对新片重跑该页 QA（旧 mp4 上的验收无效——本项目踩过：修了源码却在旧片帧上"验证"）
5. 联络表（2×2 scale 800×450）可加速复审，但必须带页码水印
6. 已知陷阱：同秒数 beat 解析键互撞（用序号）；模板 Page@N2@ 替换产生 PagePage（改模板 @NN@）；衬底必须注在 Enter 容器层而非内层 div（多行文本会裸露）；emoji 无字体；drawtext 不可用（无 libfreetype，用 PIL）

## QA 流程 v3 + 槽位工作流（2026-09-28 深夜定稿，E2 36s 错位事故后）

### 槽位驱动渲染（根治错位）
1. **GPT 出板时必须同时输出 `page_XX_slots.json`**（每页全部空白文字槽：x/y/w/h + role，板面像素）——E2 事故根因就是"只给视觉板没给槽几何"（GPT 自认责任）
2. 兜底：`detect_slots.py` 粗粒度墨密度检测可自动找槽（顶部横幅+底部条全系列通用 (464,128,792,120)），但卷轴内部子槽等细节区检测不到 → 用 GPT 坐标，检测器做交叉校验
3. 渲染一律走 `SlotPage.tsx` 通用组件 + `pages.config.ts` 配置：槽位坐标→CSS 的映射系数从真实板面尺寸现算（cover 补偿），**禁止手写像素坐标**
4. FitText 字号自适应槽宽（CJK 字宽≈字号），杜绝换行溢出；槽内 flex 垂直水平居中

### 节拍锚点（时序错位根治）
- `bounds` 锚点**直接绑定口播时间线**（每段旁白起止秒 → design 秒 = sec/页长×design总长），锚点数量 ≥ max(beat index)+1
- E2 事故：bounds 8 锚点但 beat 引用到 8 → b[8]=undefined → 元素永不渲染（右卷轴整列消失）

### QA 流程 v3（渲染后必跑，顺序执行）
1. 全局：ffprobe 时长 vs 帧数/30 ±0.5s；volumedetect max>-6dB
2. **数值 QA**：`bun -e` 从 pages.config.ts 生成镜像 → `numeric_qa.py` 断言 42+ 项 fit/containment，**0 FAIL 才继续**
3. 视觉 QA：`qa_frames2.py` 抽每页 late 帧（音频末-0.6s）+ mid 帧，PIL 烧页码水印 → 逐页带预期清单 PASS/FAIL
4. FAIL→修→**重渲染**→只重验 FAIL 页（旧 mp4 上验证无效，踩过）
5. 抽帧放大裁切（zoom crop）是终审手段：整帧缩略图上视觉模型会漏报/误报 22px 级文字

### 环境陷阱备忘
- relay 浏览器 file:// 页面**禁所有 JS**（CSP）→ 校准页/测量页必须走本地 http.server
- relay 中继 file:// 导航偶发 20s 超时 → 重试即可
- drawtext 不可用（无 libfreetype）→ PIL 烧标签
- ChatGPT 空回复故障 → 同会话补"请重新完整输出"；附件上传中不要按发送（会丢附件）
- GPT 会话加载失败"无法加载此对话"= 网络抖动 → 点重试/稍后再试

## QA v3.1 补充（E3 青龙桥复盘，2026-09-29）
- **时序抽帧必须用当集页长表**：每集页长不同，跨集复用旧 starts 表会抽错页（E3 复盘：把安河桥页长用在青龙桥上，36s 实为 P2 第 10.5s，误判"右卷轴空缺"）
- **beat 三义混用根治**：SlotPage 已改为**序数均布时序**（配置顺序=出场顺序，均匀分布整页时长），beat 字段废弃；锚点越界类 bug 从机制上消灭
- **视觉 QA 噪声对策**：a) 同一坐标两轮报告矛盾时，用 ffmpeg zoom crop 直接目检仲裁；b) 预期清单喂给视觉模型会诱导"找到"不存在的条目 → 终验用开放式描述（"客观列出可见文字块"）
- **分辨率三空间**：板 1672×941 / 视频 1920×1080 / QA 帧 1600×900——映射系数一律代码现算，禁手算
- **GPT 坐标不可信现象**：GPT 对自己生成的板给出的槽坐标曾把文字导回插画区（P2 卷轴）→ 槽位以 detect_slots.py 检测 + 渲染抽帧仲裁为准，GPT 坐标仅参考

## QA v4 补充（E8 高梁桥研究闸门复盘，2026-09-29）

**本项目最重要的一次闸门拦截**：E8 研究档案 v1 送 GPT 复查，得 PASS WITH EDITS + **16 条硬错误**。其中 3 条会直接让片子说错话：

1. **"桥下就是 979 战场"** → 战场只能定位"古高梁河畔"，具体位置有多种说法；"313 年后同一地点"同样不成立
2. **"元代闸桥至今仍在服役"** → 闸已毁；桥 1980—82 年大改（曾北移约 1 米重建）
3. **"紫竹院湖到积水潭今称南长河"** → 高梁桥是长河/转河的分界点，河名范围写反

另修正：1292 非绝对始建（金承安三年 1198《金史》已有"勿毁高梁河闸"）；牌坊"姿安"→**"资安"**；袁宏道篇名《琼花斋集》→**《游高梁桥记》**；"辽保宁十一年"→**辽乾亨元年**；"休哥因伤未追"与史载不符（辽军仍追至涿州）；乘驴车=[文献记载]/中箭=[后世记载]须分级；《帝京景物略》为刘侗、于奕正同撰；倚虹堂（桥西）≠船坞（南岸）；现桥尺寸数据冲突不可单列；"国保大运河子项"≠"世界遗产点"。

### 闸门意见必须逐条独立核实（E10 新增，2026-09-30）

### 另一个反复出现的坑：把"等级最高""之首"当史实

E10 原写「西顶是五顶**之首**」「北京**等级最高**的一处碧霞元君庙」——闸门判**无史料依据**，全数删除。
这类**评价性拔高**（之首、最高、最早、最大）在历史类档案里极高危：听起来合理、无法证伪、但会被口播成"史实"。

> **处理办法**：换成可证的**位置事实**。
> 例：「西顶是五顶之首」→「西顶是**五顶中唯一在海淀的**一座，且是唯一紧邻清代军事营房的」。
> 同样适用于"最早/最大/最长"——除非有官方名录或测绘档，否则一律改写为可核的具体事实。

## E9《大钟寺》研究闸门复盘（2026-09-29）

### 核心主题（区别于普通"古寺介绍"）
一口 46 吨明代巨钟在四个空间里被四种方式解释——**器物本身几乎没变，变的是它所处的空间与人们读它的话**。
史学内核：1743 迁钟 → 1746 乾隆《大钟歌》才把钟与靖难、忠臣、忏悔绑定，**解释比器物晚三年**，这正是本集的立论。

### 复查战果（PART1 13 条 + PART2 16 条硬错误，全部修正）
比 E8 更密，且撞出四处会让片子说错话的核心错误：
1. **"钟在地上躺了三百年"** → 1607 迁万寿寺后**正常悬挂撞击**，天启年间才因讹言弃置，**卧地约一百二十年**
2. **1733 开工 ≠ 1733 赐名觉生寺** → 雍正十二年（1734）冬告成赐名
3. **1743 迁钟 ≠ 1746 大钟歌** → 乾隆十一年（1746）才出现把钟与靖难、忠臣、忏悔系统绑定的长篇诗；1743 时那首还只是佛教语汇
4. **"永乐大钟＝皇家祈雨法器"** → 2023 年大钟寺古钟博物馆专项课题重新核档，**明确纠正"非祈雨不鸣"的讹传**；可落实的祭坛祈雨起点是乾隆四十三年（1778）寺西墙外设坛

其余修正：钟高取博物馆口径 6.75 米（不与 5.5 米平均）；铸年只说"永乐年间"（1424 非学界定论）；铭文用"23 万余字"（不混用 230,184 / 231,666 两套统计）；铭文是**铭铸**不是雕刻；"铭文纯是经咒"错（钟上有年款与政治祈愿语，特殊处是**无臣工署名**）；悬挂不得说"全靠一根纯铜销"（有 U 形连接件+钢芯）；金银"防锈/增流动性"是现代观点非明代意图；姚广孝监造是晚明文献记载但缺同时代证据（非民间传说）；铸钟厂铸成说标[研究推断]；万寿寺 1577 开工 1578 竣工；"日供六僧"不得扩写为"六人同时撞钟"；不得说"从皇家法器变民间法器"（万寿寺是皇家寺院）；**"华严钟"之名"至少到晚明已流传"而非"起源于万寿寺"**；不得替袁宏道编造"未钻到钟内"的观察过程；"先安钟后建楼"标[研究推断]；删除 1787 辟祈雨说；"政治空间/物证"是现代研究观点非清廷自白；"高度一致"改"大多相似"；不得说大钟寺展品多为寺内原物。

### 研究档案写作纪律再升级（E9 新增）
- **三套证据必须分层，绝不混级**：①钟本体铭文＝明代一手实物 ②乾隆御制诗碑＝清代对明代器物的一手解释 ③"政治空间/物证/忠君宣传"＝**现代学者分析**。混级就会把 2022 年的论文结论写成 1746 年的清廷自白。
- **"区间取值"是伪严谨**：两个数据源冲突时不要取中间值（"高约五到七米"显得比单一数字更不可靠），应采用权威机构现行公开口径并说明差异来源。
- **"刻"vs"铸"要分清**：铭文是制范时铸成的阳文，写成"刻"即技术性错误。
- **四阶段/多阶段模型**（如"皇家佛事法器—民间佛事法器—…"）是现代研究的概括框架，不是历史机构分类，不可当史实陈述。
- **"X 的功能"要从"X 所在场所的功能"中独立验证**：寺是祈雨场所 ≠ 钟是祈雨法器。E9 由最新档案研究证伪。
- **夸张的时间跨度表述极易出错**（"卧地三百年"）：先核该器物在各阶段的实际状态，再算时长。
- **二手数字可能自相矛盾**：同一维基条目的两个页面可以给出不同年份（1577/1607、1743/1751），必须回到《日下旧闻考》《酌中志》等原始文献。

### E9 流程性经验（2026-09-30 实跑验证）
1. **配额窗口到达不等于立刻可用**：窗口开于 10:45，实际 10:53 第一张才出图。窗口到达只意味着"可以试"，仍需按"先发一张验证"的策略试探。
2. **等待器的判据要用「blob 图片数量增长」，不能用「停止按钮」**：出图阶段按钮的 `aria-label` 仍是「停止」，而**文本/代码回复阶段该按钮会消失**。用"停止按钮是否消失"判完成会把已出图误判为未完成（E8 实际误判过一次，多花了约 10 分钟）。
3. **发送按钮有三种标签**：`发送`（空输入框时禁用）、`停止`（已插入未发送 / 发送后生成中）、无。脚本不能只找「发送」——文本已插入但按钮仍是「停止」时说明**上一次其实已发出**，再去重发会导致重复。
4. **取图直接走 blob fetch，不要点下载**：页面里 `<img src="blob:...">` 可直接 `fetch` 拿字节再落盘，避开下载目录管理。E8 三张共约 9MB，全部一次成功。
5. **`/backend-api/conversations` 接口被拦**（返回空），但**侧边栏 DOM 里的 `a[href^="/c/"]` 可读**（能拿到最近 20 个会话的 id 与标题）。要找回历史会话，用侧边栏 + 滚动，不用 API。
6. **虚拟滚动会卸载旧轮次**：`main` 的 `innerText` 只保留最近几屏，早前的槽位 JSON 取不到。所以**每页槽位拿到就立即落盘**，不要攒到最后一起抽——E8 的 P8 `usage` 字段就是这样丢的（被自己的 sed 截断），只能回研究档案手工补回。
7. **E8 真正的阻塞点不是缺图，是文件名**：`SlotPage.tsx` 找 `page_XX_layout.png`，而板面产出是 `page_XX.png`。补图时必须按 `_layout` 后缀落名，否则渲染时静默用空白底。
8. **槽位几何在两次独立生成间完全可复现**（E8 P2/P7/P8 重新生成，25 个槽位的 x/y/w/h 与首轮零差异）。可以把"槽位几何"视为**可持久化资产**，不必重新生成。
9. **视觉模型会质疑给它的事实源**：E8 验收时它反问"979 年应是辽景宗非辽太宗""至元二十九年非至元九年"——**但旁白原文是对的**，是我给代理的事实源简写有误。给它做验收时，**事实源必须逐字对齐原文**，否则会得到基于错误前提的 FAIL。
10. **板面必须留白，文字在 Remotion 运行时填槽**：这是全系列的既定分工。验收时"框里没有字"**不是缺字问题**，反而要专门检查"该空的地方是不是真的空着"（E8 P2 的 PNG 纪律就是禁止出现「高梁水/永定河/长河/转河/水经注」）。

### E8 终渲染 QA 的两个真缺陷（2026-09-30，v1→v3）
1. **分页累积漂移（最严重，浪费两轮渲染）**：`pages.config.ts` 的 `bounds` 起点每页比实际音频起点晚 **0.4s**，逐页累积到 P7 达 **+9.6s（288 帧）**。症状极具误导性——抽 P7 的帧看到的是 **P8 的内容**，于是 8 个验收代理里有 5 个报"槽位空字"，看起来像渲染失败，实际是**看错了页**。
   - **根因链**：`PAGE_DURATIONS_SEC`（音频+1.6s 留白）→ `pageOffsetFrames` → `bounds`，但 `bounds` 被当成了"含留白的页起点"。留白是**页尾**的，不该计入下页起点。
   - **修法**：`bounds` 起点 = 前序各页**纯音频时长**累加（不含 1.6s 留白）。P8 起点 4226 帧 = 140.87s。
   - **教训**：`bounds` / `pageLenSec` / `PAGE_DURATIONS_SEC` **三者必须同源**，且同源数据要写明是"纯音频"还是"含留白"。留白只加在 `PAGE_DURATIONS_SEC` 一处，下游自行处理。
2. **槽位对比度不达标**：`railway_1905` 是 P7 四个年份项中**唯一**没用 `backing: true` 且用 `SOFT` 淡色的，字压在铁路工人插画的碎石与人物轮廓上，终态帧实测"1905"几乎不可辨。改为 `INK` + `backing: true` 后清晰可读。
   - **教训**：**同页同类槽位的样式必须一致**。`railway_1905` 漏配 `backing` 是人工漏项，视觉验收才抓到——代码不会报错。
3. **误报要敢于否掉**：多个代理报"标题首字被裁切"，实际是我给裁剪窗口 (80,50)-(1010,185) 切到了标题框。**放大裁切 + 读图交叉验证**是分辨"真裁切"与"我的裁剪窗口切到"的标准动作。
4. **验收帧必须取"终态帧"且时刻公式要写清**：`Enter` 按 `idx` 把 items 铺满 `anchor = 音频结束 - 0.5s`，所以中点帧必然缺字。正确时刻 = **页起点 + 该页纯音频时长 - 0.2s**。
5. **板面文件名的隐藏契约**：`SlotPage.tsx` 取 `page_XX_layout.png`，而 ChatGPT 产出的下载件叫 `page_XX.png`。补图必须按 `_layout` 落名，缺图时 Remotion **不报错**，只是静默用 `PaperBg` 兜底——这正是 E8 前 5 页能渲、第 3 页起渲不出来的真正原因。
