## 2. 归一函数设计

### 函数位置与命名
- 定义在 `qa_v2/normalize.py`。
- 新增 `normalize_script(s: str) -> str`：负责纯繁简/异体字映射。
- 重构 `normalize_punct(s: str) -> str`：
  ```python
  def normalize_punct(s: str) -> str:
      s = _STRIP.sub("", s)
      return normalize_script(s)
  ```
- **标点剥离与繁简归一管道化**：所有走 `normalize_punct` 的文本（槽位文字、OCR 读回文本、专名候选）都会自动享受繁简归一，保证两端字符集完全同构。
- **两端严格对齐**：
  - `load_names` 在加载 `names.txt` 时经 `normalize_script` 过滤。
  - `check_l4b` 中提取 `want` 目标词时对 `item.text` 和 `name` 执行 `normalize_punct`。
  - `check_l4b` 比对 OCR 读回文本时统一通过 `normalize_punct`，消除「正黄旗」与「正黃旗」的字符编码分歧。

## 4. 繁简表的已知局限

1. **有限字典覆盖**：
   - 汉字繁简对照有数千对，静态字典无法穷尽所有生僻字或特定典籍中的异构字。
   - 下一集若出现未收录的冷门地名/官职字（如某个未在常用字表的古建筑构件名或清代旗营专门用字），仍需在 `TRAD_TO_SIMP` 补充。
2. **一繁多简 / 一简多繁的歧义**：
   - 字典采用繁体到简体单向映射，未引入基于上下文分词的繁简转换（如 OpenCC）。对于极少数多音/多义繁体字可能存在潜在语义折叠，但在历史片槽位短语核验场景下，单向归一到简体是确定且充分的解法。
