# 对抗检查 agent 派发模板

> 配套流程：`.superpowers/sdd/three-stage-review-workflow.md`
> 技能：`one-writer-two-adversaries`
> 用法：复制下方两个 prompt 块，替换 `<...>` 占位符，并行派发。

---

## ⚠️ 派发前必查

- [ ] 主写 agent 自测**全绿**（贴了真实数字）——这是门票，不是免检证
- [ ] 两个 agent 的任务描述里**都写明互不可见**
- [ ] 分工**不重叠**（一个查事实层，一个查判据/管线层）
- [ ] 每个 agent 的 prompt 里都带「**不得编造问题充数**」

---

## Agent A：证据层

```
你负责【<EP>】交付物的**证据层**对抗审核。另一个检查 agent 在管判据/管线层，
不要越界，也不要去读它的结论——你们互不可见。

# 交付物
<逐个列出文件路径>

# 铁律
1. 只读不改，发现的问题写进报告，由主 agent 修
2. **必须 web_search 逐条核外部事实**，不能只读本项目文件就下结论
   ——只读内部文件就下结论等于复读主 agent，不构成对抗
3. **不得编造问题充数**。找不到真问题就明说「这一项我核不出问题」。
   虚假的「疑似问题」比漏报更有害：它浪费修复时间并淹没真问题
4. 但不许放过真问题。每条必须给**可验证证据**（文件:行号 + 外部 URL）
5. 必须报告「核过但认为没问题的项」——这告诉主 agent 你的覆盖面
6. 不要 git commit

# 必查清单
- [ ] 每处年代、人名、文献名、版本、卷次
- [ ] 编号/级别类属性：<本项目的批次体系陷阱>
- [ ] 「最大/最早/唯一/至今仍在」类最高危表述
- [ ] 名相考订（<本项目的专业领域>）
- [ ] 空间关系：事件地点的地物是否在事件**之后**才存在
- [ ] 保护对象 ≠ 所在地点
- [ ] 定性越界：证伪必须有反驳证据；absence of evidence ≠ evidence of absence

# 方法论
先读 skill://detector-needs-negative-control，按其纪律执行。

# 历史教训（本项目已踩过，你的审核要专门查是否复发）
<抄本项目历集的坑>

# 交付
报告写入 <PATH>
最终回复给出：按 🔴🟡🔵 排序的问题清单（每条含 位置/问题/证据/建议）、
你核过但无问题的项、报告字节数。
**不要粘贴报告全文。宁可清单短而实，不要长而虚。**
```

## Agent B：管线与判据层

```
你负责【<EP>】交付物的**管线与判据层**对抗审核。另一个检查 agent 在管证据层，
不要越界，也不要去读它的结论——你们互不可见。

# 交付物
<逐个列出文件路径>

# 铁律
1. 只读不改（临时验证用的文件用完即删）
2. **必须实际运行**测试和抽帧，不能只读代码
3. 临时构造破坏性数据时，**必须在报告里说明动过什么并确认已恢复**
4. **不得编造问题充数**
5. 不要 git commit

# 必查清单
## 恒真检测（最重）
- 逐条问：把数据全反过来，这条断言还能不能通过？能 → 恒真
- 自己造一个悬空引用/错误数据试试（用完即删）

## 渲染结果
- 抽终态帧（<本项目的时间计算公式>）
- 文字溢出/被裁切/压在图上/该出字的槽是空的
- 同类项样式逐项对齐：<本项目的易漏配属性>
  ——漏配**不会报任何编译错误**，只在成片里表现为不可读
- 字幕条是否遮挡内容

## 资产防伪
- 「实物照片」是否其实是绘制件
- 示意图里有没有编造的碑刻/引文
- 「书影」是否伪称原件扫描

## 代码与配置
- 布尔 filter 逐 case 验（if not x or "k" not in x 会短路）
- 阈值下限是否让小数量完全逃过检查
- 归一函数是否吞掉语义相邻的实体
- 禁词表是否可被同义说法绕过
- 关键词扫描是否限定了作用域

# 特别指定核查（本轮已怀疑的点）
<逐条列出本轮自己拿不准的怀疑点，让它证实或证伪>

# 方法论
先读 skill://detector-needs-negative-control，按其纪律执行。

# 交付
报告写入 <PATH>
最终回复给出：问题清单（按 🔴🟡🔵）、判据健康度专项结论
（有没有恒真的、有没有问错问题的）、报告字节数。
**不要粘贴报告全文。**
```

## 修复阶段的提示

检查结果回来后，主 agent 逐条处置：

| 情况 | 处置 |
|---|---|
| 🔴 属实 | 立即修，修完复跑全部验收 |
| 🟡 属实 | 修，或写明不修的理由与依据 |
| 🔵 属实 | 顺手修 |
| **检查 agent 判断错** | **不修**，在进度文件里记明「该条为误报」及反驳依据 |

**不要为了让检查 agent 满意而改。** 检查 agent 也会判断错——
但那时它会给出证据，你可以反驳；无证据的「建议」不构成修改理由。

修完把结论回写到 `.superpowers/sdd/<ep>-adversarial-fix.md`：
逐条列「改没改」，不能只写「已处理」。
