## 2. A07 bug 根因(m20b_a07.py 冠弧锚粗拟)

复现: `python3 m20b_a07.py pose <frame> tag -1` → 0.6s 内 `TypeError:
'NoneType' object is not subscriptable`(best_a=None)。三处叠加:

1. **参数个数不匹配(直接死因)**: `cam_model_proj(np.append(p[:6],0.0),…)`,
   cam_model_proj 只收 6 参([az,el,Cx,Cy,Cz,f]), 传 7 参每种子当场
   `ValueError: too many values to unpack (expected 6)` → 被
   `except Exception: continue` 全部吞噬 → best_a=None → 崩。
   (另: cam_model_proj 对 (n,m,3) 输入返回 (n,2,m), 原逐锚循环用法与
   向量化用法都需按 [.,0,:]=u/[.,1,:]=v 取用。)
2. **bounds 卡死种子**: Cy∈[-60,60] 把 dist≥80 的种子判 infeasible
   (least_squares trf 对 x0 越界直接抛 ValueError, 同被吞)。
3. **目标函数退化**: min-dist-to-arc 的 rms 目标在近孔大弧离轴时爆残差、
   远机位处 9 条冠弧塌缩成一点 —— 朴素 rms 与 clamp+中位数两种目标都被
   吸引子收编(实测全种子收敛到 f=700/bias=160 边界角)。

修复(隔离树副本): 修 1/2 + 异常计数不吞 + best_a=None 跳过 + 网格预排序;
目标函数塌缩问题按 §1 改道冠锚 PnP(该路径有 2017 A08 先例背书)。

## 4. 实测协议与 stones v4 结果

## 7. 遗留与风险

1. p6 c9/c10/c14 的 z0 采纳各有 1 帧强度相当的反向读数(mad 更小者反而在
   异帧侧, 如 c9 f675 mad=0.002) —— 密集顶层带(层距 0.236m ≈ 6-7px 源像素)
   谷线身份固有歧义, 已按协议采纳多数并在 _trace 记异帧; 若后续拿到 4K 源
   应优先复核这三层。
2. 竖缝 3 条中 p7 c13 −11.88 处于模糊极限; 更高分辨率帧可裁定。
3. f150 位姿 rms 7.13px(≈0.2-0.3m@24-36px/m)由冠锚亮边偏置主导; zfit 的
   三帧一致性已吸收该系统偏差, 但单帧绝对 z0 不宜直接外推到未测孔。
4. A07 连续粗拟路径(m20b_a07.py)修复后仍未收敛到可用解(目标函数本身退化),
   本轮以冠锚 PnP 替代; 若将来需要该路径, 建议直接删除连续粗拟、保留
   离散 a0 扫描 + 冠锚 PnP。
