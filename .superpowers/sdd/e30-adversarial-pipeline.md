## 🔴 发现（按严重度）

### 🔴1. P5 立论数字「桥轴实测 103.15°」被两个独立证据推翻，真值 ≈112°
- **位置**：research.md:155-158（端点表）、161-164（103.15°/166.4m/桥心）；design.md:316（ang_measured "103.15°"）、324（databoard 第 1 行）、282（口播「桥的走向是一百零三点一五度」）
- **问题**：§12 的两个「目视端点」都不是桥端：
  - 西北端取点 (116.270300, 39.989860) 落在**南湖岛南岸**，偏离真实西桥台 ≈41 m（WNW 向）；
  - 东南端取点 (116.272200, 39.989520) 偏离真实东端 ≈29 m（正北向，取到了北缘/岸线）。
  两处误差同向把桥轴往正东-西方向压，恰好造出 103.15°。
- **证据**：
  1. OSM way 187196435「十七孔桥」（wikidata Q61857626）端点 116.2707389,39.9897170 → 116.2721945,39.9892614：**az=112.15°，跨水长 134.0 m**。
  2. 用 §12 自述参数（bbox 116.2680/39.9880–116.2830/39.9960，1500×800，imageSR=4326）今日重新导出同一影像，桥面亮带 PCA 拟合：**az=111.85°**——与 OSM 差 0.3°。两条独立路径一致。
  3. 复现项目链条：其像素取点 Δ=(190,34)px 经各向异性比例尺（x=0.853、y=1.109 m/px）换算 → az=103.10°/166.4 m，与其发布值 103.15°/166.4 m 吻合——**算法没错，错在取点**。
  4. research.md:154 自称「精度约 ±5 m」：实际西端差 41 m、东端差 29 m，超一个数量级。
- **附带**：§12:151 称「桥为夏季晴空影像，无冰面遮挡」——同一端点今日导出的影像**满湖冰封**（桥面仍可见，但其「夏季无冰」的选源理由不成立）；「0.86 m/px」与自述 bbox 在 y 向不符（y=1.109），文档链自相矛盾。
- **建议**：端点改取桥台（可用 OSM 节点或影像上桥面亮带端点），重算后 az≈112°；同步改 §12 全部数字与「夏季影像」表述；把端点坐标+导出 URL 落成 `geo/axis_measure.py` + JSON（见 🔴3）。

### 🔴2. 「几何最优 118°–120°」全库无推导，是本页立论的承重墙上的空洞
- **位置**：research.md:176（「若真是为冬至日落定向，最优应在 118°–120° 附近」）；design.md:279、282、318-319（ang_optimal「约 118°」）、294（灰紫指针 118°）
- **问题**：全项目（含 geo/ 全部脚本、research.md 两张表）**没有任何判据、任何一行代码推导出 118–120°**。research.md 自己的两张表反而显示：侧照角随桥轴 90°→115°→120° **单调递减**（58.72→33.72→28.72），按此趋势真正的「最优」是 **148.72°**（法线 238.72° 正对冬至日落，侧照角 0°、cos=1.0）——在任何约束下都轮不到 118–120°。§11:145-146 也自认「118° 是我按定性推的」，但 §12/design 随后把它当计算结论讲（「最优应该在一百一十八度左右」）。
- **更深层（问错的问题）**：「为冬至设计→轴角应取最优」这个提法本身是伪框架——桥连接东堤与南湖岛**两个固定端点**，轴角不是可自由设计的变量；可设计的只有岛和堤的位置。以轴角单变量求「设计最优」是比较学，不是设计学。
- **建议**：要么给出明确判据（如「在官方『西北—东南』象限约束内最小化侧照角」→ 那最优是 135°，不是 118–120），要么改写立论：用「冬至日落 238.7° 与桥面法线（~202°）相差 ~37°、与桥轴相差 ~127°，与任何『对日定向』配置都不吻合」——这个真实版本其实比「差 15°」更有力。

### 🔴3. 「差 15°」不成立：修正后差 ≈6°，与其自报测量不确定度同量级 → P5 需重构而非改数
- **位置**：design.md:282（口播「差着十五度」）、320（ang_gap「差 15°」）、297（「核心数字」圆弧）、324（0.700）、327（193.15°）
- **问题**：按真值 az≈112.15°：法线 202.15°，冬至侧照角 **36.57°**（非 45.57°），有效入射分量 **cos36.57°=0.803**（非 0.700）；与「最优 118.15°」的差 = **6.0°**（非 14.85°）。而其自报端点精度 ±5 m 折合角度不确定度 ≈±2.1°（按其 §11「±8 m」口径则 ±3.4°）——6°±2~3° 的差值**不足以支撑「不是为冬至设计」的决定性表述**。原 15° 看似决定性纯属两个误差叠加的巧合。
- **连带需改**：design.md 324（databoard 三行中两行）、327（yearband「永不到达 193.15°」→ 202.15°）、294-295（罗盘指针角）、316-320（槽位 usage 文案）、282（口播）、约束 10/11/20 相关表述；research.md:169-177、181-184。
- **建议**：先重做测量（🔴1），再决定立论等级（🔴2 的两个改法二选一）；重测+判据确定后，把「实测→导出」全链落成脚本，兑现 design.md:517 约束 20 的「三行数字全部可复算」——目前 103.15/166.4 **在仓库中无任何脚本、无端点文件、无导出 URL**，只有散文两行。

## 🟡 发现

### 🟡1. slotcheck 存在静默跳页恒真路径：解析不到的页 = 不存在的问题
- **位置**：slotcheck.py:18-21（parse_slots 正则）、main()
- **证据（M5 实测）**：把 design.md 副本中 `"p01"` 改为 `"P01"` → 校验器输出「解析到 7 页」，p01 的 9 个槽**静默消失**，其余页全过，**exit 0**。若围栏格式整体变化则「解析到 0 页」同样 exit 0——判据缺前置数据时报 pass，正是 detector-needs-negative-control 点名的反模式（返回空=无问题）。
- **建议**：main() 断言 `set(pages) == {p01..p08}`（页数或页名清单来自设计页数），不符即报 FAIL/skip；0 页必须非零退出。

### 🟡2. pierce.py 的「核心判据」count_lit 测的不是本集宣称的机制，且与自家 header 矛盾
- **位置**：pierce.py:43-53（count_lit，判「太阳方位≈桥轴」）；pierce.py:6-19（header 明言「光不必穿孔、判据不是方位夹角接近 0」而是侧照）；test_geo.py:104-119（两条负控制守着这个模型）
- **证据**：以真实桥轴 az≈112 调 `count_lit(112.15, 238.72)` → **0 孔亮**——按仓库自己的「核心判据」，被无数实拍证伪的现象不可能发生。count_lit 验证的是民间「沿轴穿孔」说法（恰是 header 开头声明放弃的模型），测试给它背书 = 判据在测别的东西。
- **连带**：pierce.py:98 `need = half_gap_required(max(0.5, BRIDGE_H_M * 0.0 + 0.5))` 死代码（恒 0.5°，结果从未使用）；`pierce_window` docstring 承诺「夹角阈值 + 高度角须低」过滤，实现无阈值、无过滤、返回全年每天；`half_gap_required`（真正的「光能否进洞」判据）无测试、无调用方——即「0.700 这个数到底够不够穿洞」在本管线中**从未被任何判据回答过**。
- **建议**：删 count_lit（或标注为民间模型道具并从「核心」降级）；实现侧照进深判据（如 `宽度×tan(侧照角) vs 净跨`，at λ=36.57°: 6.56×0.743=4.87 m < 5.8 m 净跨 → 恰好能打进内壁——这才是 P5 该展示的几何）并配测试；清死代码。

### 🟡3. §13 照片时间自检「日落前 28 分钟」与其自家星历矛盾（实为 ~16 分钟）
- **位置**：research.md §13（EXIF 2020-12-21 16:32:50「正值冬至日落前 28 分钟」）
- **证据**：solar.py 冬至日落 16.81 时 = 16:48:36 → 16:32:50 差 **15.8 分钟**；按含折射目视日落（≈16:54）也只差 21 分钟；任何口径都到不了 28。
- **建议**：改「约 16 分钟」；此条属证据层素材，但它是星历自检链的一环，两审都点到为止不如这里留档。（另一审的 A 组条目若覆盖 §13，以其为准。）

### 🟡4. 测量工具链引用了不存在/误导性的工件
