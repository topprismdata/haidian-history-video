# 三段式制作流程：1 主写 + 2 对抗检查

> 适用范围：`haidian_kg` 系列**每一集**（E1 起，无例外）。
> 建立日期：2026-10-04（E26 交付后，用户提出）。
> 起因：E26 一次交付里被两个独立审核 agent 抓出多类问题（见 §5），
> 证明**「自己写自己验」抓不到自己犯的错**。

---

## 〇、为什么是这个结构

单 agent 从考据到成片全程自写自验时，有三类错误**结构性地抓不到**：

| 盲区 | 为什么自己抓不到 | 谁能抓 |
|---|---|---|
| **史实层** | 写的时候顺手把「查不到」写成了「应该是」 | 只做外部核对的 agent |
| **判据层** | 判据的假设对不对，只有拿真实数据撞才知道 | 只跑判据与抽帧的 agent |
| **注意力分配** | 一个 agent 同时管考据、渲染、QA，注意力被摊薄 | 拆分即解决 |

而且**两个检查 agent 必须互不可见**：如果它们互相能看到对方的结论，
就会产生「趋同」——都去确认对方已经查过的地方，漏的地方一模一样。

**分工原则：攻不同层面，不重复。** 同一层面派两个 agent 是浪费。

## 一、三段式流程

```
┌─────────────────────────────────────────────────┐
│  阶段 1：主写 agent（1 个）                      │
│  research.md → design.md → 资产 → KB → 旁白      │
│  → TTS → 槽位/分镜 → 渲染 → 自测                 │
└──────────────────┬──────────────────────────────┘
                   │  交付（自测全绿）
┌──────────────────▼──────────────────────────────┐
│  阶段 2：对抗检查 A —— 证据层（1 个）            │
│  只查史实：年代/人名/文献/文物级别/名相/地望      │
│  必须 web_search 外部核对                         │
│  输出：按 🔴🟡🔵 排序的问题清单 + 外部 URL         │
└──────────────────┬──────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────┐
│  阶段 3：对抗检查 B —— 管线与判据层（1 个）      │
│  只查判据健康度 / 渲染结果 / 资产防伪 / 遮挡溢出  │
│  必须实际跑测试 + 实际抽帧目视                    │
│  输出：恒真判据清单 + 抽帧问题 + 判据问错问题清单  │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
        主写 agent 按清单修复 → 复跑 QA → 提交
```

**两个检查 agent 并行派发**（互不可见），节省一半墙钟时间。

---

## 二、主写 agent 的义务

交付前**自测全绿**是**进入检查阶段的门票，不是免检证**。

主写 agent **必须**：
- 跑完整测试套件 + 快档/全档 QA，贴出真实数字
- 在 `DELIVERY.md` 里**主动列出已知限制**（不许只报好消息）
- 把「查不到」明确写成「未考得」，不许用「应该是」填空
- 标注每个数字/年代/文物级别的来源

---

## 三、检查 agent A（证据层）的强制动作

1. **必须 `web_search` 逐条核外部事实**，不能只读本项目文件就下结论——
   否则它只是复读主写 agent 的判断，不构成对抗。
2. **不得编造问题充数**。找不到真问题就明说「这一项我核不出问题」。
   虚假的「疑似问题」比漏报**更有害**：它会浪费修复时间并淹没真问题。
3. **但也不许放过真问题**。每条问题必须给**可验证证据**（`文件:行号` + 外部 URL）。
4. **必须报告核过但认为没问题的项**——这告诉主 agent 它的覆盖面。
5. **只读不改**。问题交回主 agent 修。

### 必查清单（E 类）

- 每一处年代、人名、文献名、版本、卷次
- 文物级别：国保批次 / 公布日期 / 编号
- **国保编号体系的批次陷阱**：1961 年第一批**无「X-YYY」式编号**
  （该体系 1982 年第二批起施行）。第一批**严禁引任何编号**。
- 「最大/最早/唯一/至今仍在」类**最高危表述**
- 名相考订（梵汉对译、地名学、器物名）
- 空间关系：事件发生地的地物是否在事件**之后**才存在
- **保护对象 ≠ 所在地点**：国保保护的是「某寺的某座塔」还是「整个寺院」

---

## 四、检查 agent B（管线与判据层）的强制动作

1. **必须实际运行**测试和抽帧，不能只读代码。
2. 临时构造破坏性数据验证判据时，**必须在报告里说明动过什么并确认已恢复**。
3. 同样**不得编造问题**。

### 必查清单（P 类）

**判据恒真检测（最重）**
- 逐条问：把数据**全反过来**，这条断言还能不能通过？能 → 恒真
- 自己造一个悬空引用/错误数据试试（**用完即删**）

**渲染结果**
- **每页抽终态帧**（页起点 + 该页纯音频时长 − 0.2s；页长**含** 1.6s/页留白）
- 文字溢出槽位 / 被裁切 / 压在插画上 / 槽位空字
- 同页同类槽位样式逐项对齐：`backing: true` 漏配**不会报任何编译错误**，
  只在成片里表现为「某个 sub 压在插画上不可读」
- 字幕条是否遮挡内容

**资产防伪**
- 「实物照片」是否其实是制作组绘制（`sources.csv` 的 note 列须标明）
- 示意图里有没有**编造的**碑刻/引文文字
- 「书影」是否伪称原刊扫描

**代码与配置**
- 布尔 filter 逐 case 验（`if not x or "photo" not in x` 这类会短路）
- 阈值下限是否让小数字完全逃过检查
- 归一函数是否吞掉语义相邻的实体
- 禁词表是否可被同义说法绕过
- 关键词扫描是否限定了作用域

## 五、这套流程实际抓到了什么（E26 实例）

> 这些**全部**是主写 agent 自测全绿、1185 测试全过之后，由检查 agent 抓出的。

### 证据层（agent A）
- **定性越界**：「唐时所铸」判 `DISPROVEN`，但若无任何文献如此说，
  应为 `UNSUBSTANTIATED`（absence of evidence ≠ evidence of absence）
- 「北京现存最大最古铜卧佛」这类**最高危表述**需逐字核
- 「香水院＝温泉后山」这类**通行考释被当定论**（E28 考订发现）

### 判据层（agent B）
- 禁词表可被同义说法绕过（「唐铸」「自唐以来」）
- 布尔 filter 短路导致 photo 槽未被过滤
- `MIN = 10` 让「五米」「六年」这类小数字完全逃过检查

### 流程层（我自己在这轮撞到的）
- **判据问错问题**：E25 的「屏显每个数字口播都要念」在 14 个单测全过后，
  真实数据炸出 19 条 fail
- **归一函数吞语义邻居**：「年号归一」把「四十年」当年号删掉，
  产生必假 fail（E25 C2 同型复发）

## 六、报告格式

每个检查 agent 写一份报告到 `.superpowers/sdd/<ep>-adversarial-<层>.md`，
最终回复只给清单，**不粘贴全文**。

清单格式：

```
🔴 致命 / 🟡 重要 / 🔵 次要
  [编号] 文件:行号
  问题是什么
  证据：外部 URL 或代码行
  建议：改哪行、改成什么

核过但无问题的项：（这一段同样重要——它说明覆盖面）
```

**宁可清单短而实，不要长而虚。**

## 七、派发模板

见 `.superpowers/sdd/adversarial-prompt-template.md`。

关键参数：
- `互不可见`：两个 agent 的任务描述里都写明「不要去读别的 agent 的结论」
- `分工不重叠`：明确列出「你只管这些，别的层有另一个 agent 在管」
- `必查清单` 直接抄本文档 §三/§四
- `历史教训` 直接抄本文档 §五
- 交付：报告文件 + 精简清单

---

## 八、豁免

以下情形**可只派 1 个检查 agent**（在 `.superpowers/sdd/progress.md` 记明理由）：
- 补做/修订既有集（历史已过两轮检查）
- 体量明显小于常规集（<3 页分镜且无知识库变更）

**新增集、补做集、以及任何引入了新判据的集，一律两轮。**
