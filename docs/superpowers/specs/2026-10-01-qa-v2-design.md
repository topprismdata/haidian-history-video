# QA v2 设计：AI 板面视频管线的七层验收

> 状态：待评审
> 日期：2026-10-01
> 动机：E11《树村》交付时发现 `qa_all.py` 存在 plate→canvas 坐标换算缺失，导致 E11 的「槽位验收 8/8 通过」是**假通过**。本设计定义替代方案。

## 1. 背景：现有 QA 测不到什么

`qa_all.py` 的判据是「槽位矩形内深色墨像素 > 40」。实测三条限制：

### 1.1 坐标空间不匹配（已修，但是真 bug）

`slots.json` 的坐标在**板面空间**（E5/E6/E11 是 1672×941，E7–E10 是 1920×1080），
而画布恒为 1920×1080，`PlatePage` 用 `objectFit:"cover"` 铺满。
原代码直接拿板面坐标切渲染帧，未做换算。

E11 P5 的实测后果：

| 区域 | 墨像素 |
|---|---|
| `qa_all` 实际采样处 | 32062（香炉与木架的**插画**） |
| 文字真实位置 | 2229 |

**94% 的采样落在插画上**。判据「> 40」在深色木纹上必然通过 → 假通过。
已修复（`qa_all.py` 加 cover 换算），修后 E11 重跑仍 8/8，但这次是真通过。

### 1.2 墨像素判据对插画底色敏感

负控制实验：把槽位挪到 P5 画面右下 `(1500,900)`（视觉上是浅色区），实测 **583 墨像素判为通过**。
原因是该处落在深色木器上。

结论：**「区域内有深色像素」不等于「该区域有属于这个槽位的字」**。
板图越暗，误判率越高。E11 的板图偏浅（P3 淡黄米色）才侥幸没翻车。

### 1.3 判据查不出内容错误

`1485` 写成 `1486`、P8「各占一处」写成「三处四处」，槽内都有深色像素，都通过。
这类错误是历史集真实发生过的（P8 算术矛盾即属此类）。

### 1.4 已知盲区

- `kind:"tag"` 槽（`evidence_tag`）被 `TAG_IDS` 直接排除，深底白字无深色墨 → **证据标签从不被检查**
- 每页只抽终态帧一帧
- 文字溢出框外（首尾行被切）不报
- 槽位重叠不报

## 2. 校准数据（E11 实测，非估计）

全部数据由 E11《树村》成片 `out/shucun.mp4` 实测得到，作为判据标定的唯一依据。

### 2.1 OCR 能力

| 项 | 实测值 |
|---|---|
| 引擎 | PaddleOCR 3.7 / PP-OCRv6 medium（`lang="ch"`） |
| 模型加载 | 4.7s（一次） |
| 识别速度 | 8.5–16.4s/页（8 页共 110s） |
| 平均置信 | 0.989（8 页加权） |
| 最低置信 | 0.350（出现在 P4） |
| 槽位归属准确率 | **93/93**（全部槽位均能把 OCR 文本框归到对应槽） |

### 2.2 `rec_boxes` 格式

PaddleOCR 3.x 的 `rec_boxes` 是 **`[x1, y1, x2, y2]`**（右下角坐标），不是 `[x, y, w, h]`。
实测：按 `[x1,y1,x2,y2]` 解释得 93/93 归属；按 `[x,y,w,h]` 解释得 **0/93**。

### 2.3 噪声类型

**仅标点规范化**。实测样例：

| 原文 | OCR 读回 |
|---|---|
| `树村·圆明园正北` | `树村.圆明园正北` |
| `一棵树，三重身份` | `一棵树.三重身份` |
| `楹＝间` | `楹=间` |
| `「著移驻树村」` | `「著移驻树村」`（一致） |

无错字、无漏字、无繁简混淆（`鐡磬`→`鐵磬` 属正常繁简等价）。

### 2.4 文本几何余量

修复坐标换算后，93 个槽位的墨像素分布：

| 分位 | 墨像素 | 相对阈值 40 |
|---|---|---|
| 最低（`p03.r3_hall`，内容「65」） | 104 | 2.6× |
| 中位 | 636 | 15.9× |
| 最高（`p06.scroll_bottom`） | 5685 | 142× |

阈值 40 有 2.6 倍余量，对「数字最少的一格」仍安全。

## 3. 目标

在 E11 上跑出**可信的**验收结论，并能在 E12 及后续每一集直接复用。

「可信」的含义：
- 每个结论可复现（同一输入两次跑出同一结果）
- 每条判据有正控制与负控制验证（不是恒真）
- 已知盲区显式声明，不假装覆盖

## 4. 非目标

- **不做史实校验**。「1485」和「1486」哪个对是研究问题，不属 QA。QA 只保证「图上写的就是文案里写的，文案里写的就是设计稿里的」。
- **不做全历史集回溯**。本设计以 E11 校准，E5–E10 在后续集接入时再跑。
- **不替代人工目视**。自动化捕捉机械性错误，目视捕捉设计判断。

## 5. 架构

七层检测器，各自独立、可单独启停。共用一个 `slots.json` / `pages.config.ts` / 渲染帧 的加载层。

```
                    ┌─ L1 数据一致性 ─┐  纯数据
                    │  L2 几何可行性  │  <0.2s/页
                    └────────────────┘
                    ┌─ L3 渲染存在性 ─┐
   渲染帧 + 槽位 →  │  L5 溢出检测    │  ~1s/页（无 OCR）
                    │  L6 tag 槽判据  │
                    └────────────────┘
                    ┌─ L4 内容闭环 ──┐  需 OCR
                    │  数字严格      │  ~10s/页
                    │  专名严格      │
                    │  字幕交叉      │
                    └────────────────┘
                    L7 字幕/音频 —— 复用 verify_subtitles_asr.py
```

### 5.1 分层与开关

沿用 `qa_all.py` 的入口，加开关控制强度：

```bash
python3 qa_all.py shucun              # L1+L2+L5+L6（快档，~1s/页；不含 L3/L4）
python3 qa_all.py shucun --ocr        # 加 L3+L4（~2min）
python3 qa_all.py shucun --full       # L1–L6 + 触发 L7
python3 qa_all.py shucun --json       # 机读输出（供未来 CI）
```

默认不开 `--ocr`：快档包含 L1/L2（纯数据预检）与 L5/L6（无 OCR 的渲染图层检查），跳过依赖 OCR 的 L3 与 L4。OCR 是唯一慢的层，且只有「文案会改」的集才需要；快档用于秒级高频迭代。

### 5.2 各层判据

#### L1 数据一致性（纯数据，无渲染）

| 检查 | 判据 | 能抓 |
|---|---|---|
| 文案→槽位 | `pages.config.ts` 的每个 `slotId` 必须存在于 `slots.json` | E11 实测踩中：`badge`→`evidence_tag` 改名漏改文案侧，`boxOf` 静默兜底 |
| 槽位→文案 | `slots.json` 的每个槽位 id 必须被文案引用 | 静默空洞 |
| 越界 | 槽位矩形须在 `plate` 内 | 手误 |
| 异常尺寸 | 槽位 `w<40` 或 `h<20` 报 warn | 坐标错位（改名后残留旧坐标） |
| 重叠 | 任意两槽矩形交叠面积 / 较小者 > 5% 报 fail | 手误叠加 |
| 平台一致性 | `subtitles.ts` / `pageMap.ts` 存在且页数 = 槽位数 | 漏集 |

**实测 E11 当前状态**：重叠 0、越界 0、异常尺寸 0、双向一致性 93/93 全通过。

#### L2 几何可行性（纯数据，无渲染）

从 `pages.config.ts` 估算每个槽位装不装得下：

```
行数 = 文案含 \n 时的实际行数，否则 ceil(等宽估算宽度 / 槽宽)
需要高度 = 行数 × size × lh
若 需要高度 > 槽高 × 1.15 → warn（可能溢出）
```

这是**渲染前的预检**，能在不渲帧的情况下提前发现文案超框（E11 的 P4/P5 曾各有一处）。

#### L3 渲染存在性（需渲染帧）

在 cover 换算后的槽位矩形内，要求存在 OCR 文本框。

判据：**该槽的矩形内（容差 25px）至少有一个 OCR 文本框的中心点落入**。
不用「墨像素」——那是 L1.2 已证明不可靠的。

#### L4 内容闭环（需渲染帧 + OCR，用户选择「全量严格」）

三路子判据，**任一不通过即该槽 fail**：

**L4-a 数字严格**

数字归一算法（两侧用**同一函数**，保证可比）：

```python
CN_DIGIT = {"零":0,"一":1,"二":2,"两":2,"三":3,"四":4,"五":5,
            "六":6,"七":7,"八":8,"九":9}
CN_UNIT  = {"十":10,"百":100,"千":1000}

def to_int(tok: str) -> int | None:
    """「1485」→1485；「一千二百五十」→1250；「二十三」→23。
    纯位值写法（每个字一个数字）也支持：「一七二四」→1724。
    解析不了返回 None，调用方跳过该 token 并计入 unknown 计数。"""
```

- 两侧（`pages.config.ts` 原文、OCR 读回）都过 `to_int`
- 要求 OCR 侧的数字集合 ⊇ 原文侧的数字集合
- 「1485」vs「1486」→ 集合不等 → fail
- 无法解析的 token 计入 `unknown`，超过槽内 token 数的 20% 时报 warn
  （防止归一函数有 bug 却静默通过）

**L4-b 专名严格**
- 专名定义：书名号内容、旗名（正/镶+色+旗）、寺名、地名（树村/肖家河/蓝靛厂/圆明园/海甸/安河桥…）、官名（总兵/副将/守备/护军校/参领）
- 维护在 `qa/names.txt`，**E12 起随集更新**
- 要求该槽 OCR 读回包含其专名表命中的全部专名

**L4-c 字幕交叉**
- **在口播稿原文（`narration/all.json`）上做，不在编译后的 `subtitles.ts` 上做**
- 理由（实测发现）：`subtitles.ts` 里的数字 token 大量是数组下标与行号（`01`…`99`），
  当文本 grep 会全污染；且口播稿**有意省略**部分书名（文案写《钦定日下旧闻考》，
  口播只说《日下旧闻考》），直接比对必然假阳性。
- 判据：该槽文案中的**数字 token**，必须能在对应页的口播稿里找到对应表述
  （支持「1724」↔「一七二四」的语音形式归一）
- 这是**三路交叉里最弱的一路**，因为口播与文案本就不要求逐字一致。
  判据设计为：只对数字与专名做交叉，叙述性文字不查。

#### L5 溢出检测（需渲染帧，不用 OCR）

在 cover 换算后的槽位矩形内：
1. 找该槽的 backing 底板（`rgba(247,240,223,0.92)` 亮区）
2. 底板内找深色墨，二值化后**腐蚀 1 像素**去掉描边与阴影
3. 连通域面积过滤（≥12px）去噪
4. 算墨迹外接矩形，与槽位边界比
5. 若墨迹触边（余量 < 3px）→ fail

**注意**：判据必须在 cover 换算后做，且要区分底板与文字——
E11 实测直接用「墨迹包围盒 vs 槽位边界」会量到底板的阴影（恒为 28px），
两个版本量出完全相同的数，无法区分。

#### L6 tag 槽判据（需渲染帧）

`kind:"tag"` 的槽（`evidence_tag`）是**深底白字**，深色墨判据天然不适用，
`qa_all.py` 直接把它排除 → **从不被检查**。

独立判据：在槽位矩形内要求存在**近白像素**（`min(rgb) > 200`）形成文本块，
且该块面积占比在 1%~40% 之间（防止整槽被误判为白底）。

E11 8 个 evidence_tag 槽全部有值（OCR 读到 `[文献记载]`、`[官书记载]`、
`[存疑待考]`、`[原书记载]`、`[实录记载]`、`[系列联动]` 等）。

### 5.3 报告输出

人类可读（对齐终端）+ `--json` 机读。每条结论带：

- 判据 ID（如 `L4-a`）
- 槽位 id
- 期望值 vs 实测值
- **正/负控制状态**（见 §6）

## 6. 判据可信度：正负控制

每条判据必须有**至少一个负控制**证明它不是恒真。这是本设计与旧 QA 的核心区别。

E11 实测已完成的控制：

| 判据 | 正控制 | 负控制 | 结论 |
|---|---|---|---|
| L1 墨像素（原判据） | 真槽 236 墨像素 | 插画空白区 583 墨像素 → 误判通过 | **不可用**，被替换 |
| L3 OCR 存在性 | 93/93 槽内有文本框 | **§6.1 待执行** | 未完成前不算交付 |
| L4 OCR 归属 | 93/93 | **§6.1 待执行** | 未完成前不算交付 |

### 6.1 负控制的执行方法（实现时必做，不算可选）

对 L3 与 L4 各自构造负控制，**断言检测器报「无文本」**：

```python
def negative_control(detector, slots, plate, shift=(300, 0)):
    """把每个槽位平移到插画区，断言检测器判定为「无文本」。
    平移量固定取 300px —— 超过任意板面的标题带高度，不会落回真槽。"""
    for s in slots:
        fake = {**s, "x": s["x"] + shift[0], "y": s["y"] + shift[1]}
        assert detector(fake, plate) == "no_text", f"{s['id']} 平移后仍命中，判据不可信"
```

两个判据的负控制必须**在 E11 上跑通并留日志**，否则 §9 的验收标准不成立。
实现顺序上，这一步紧跟 L3/L4 写出，不推迟到最后。

## 7. 实现计划

按依赖顺序，每步可独立验证：

1. **L1 + L2**（纯数据，无渲染）— 立即可跑通，E11 应全通过
2. **L3**（OCR 存在性）— 需抽帧，E11 应 93/93
3. **L5**（溢出）— 需调参，E11 应 0 溢出（当前文案已压过）
4. **L6**（tag 槽）— E11 应 8/8 有值
5. **L4**（内容闭环）— 最复杂，需要专名表 + 语音数字归一
6. 补齐 L3/L4 负控制
7. 扩展到 E5–E10（下一集接入时）

## 8. 风险与已知限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| OCR 速度 10s/页 | 全片 QA 约 2 分钟 | 默认不开 `--ocr`；结果缓存到 `qa_cache/<ep>.json` |
| PaddleOCR 版本差异 | `rec_boxes` 格式可能变 | 在加载后断言 `boxes[0][2] > boxes[0][0]`；失败则显式报错而非静默 0/93 |
| 专名表需人工维护 | 新集漏填则 L4-b 漏检 | 专名表缺失时 L4-b 报 **skip 而非 pass**，并提示补表 |
| L4-c 字幕交叉易假阳性 | 口播与文案本不逐字一致 | 只对数字与专名交叉，叙述性文字不查 |
| 篆书/异体字 | P4 的「蜀」字碑置信 0.350 | 该类在插画上不属槽位，L4 不涉及 |
| 判据阈值可能过严 | 历史集大面积报错 | 分 `fail` / `warn` 两级，warn 不阻塞退出码 |

## 9. 验收标准

- E11 跑 `--full`：L1–L6 全部通过，L7 由既有脚本通过
- L3/L4 各有负控制证明非恒真
- 故意破坏一个槽（如把 `1485` 改成 `1486`）能被 L4-a 抓出
- 故意把文案加长一行能被 L2 或 L5 抓出
- 故意让两个槽重叠能被 L1 抓出
- 运行时长：快档 < 5s/集，`--ocr` 档 < 3min/集
