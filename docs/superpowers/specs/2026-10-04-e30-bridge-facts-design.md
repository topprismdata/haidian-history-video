# E30 十七孔桥 模型质量工程 设计（spec）

日期：2026-10-04
状态：待用户审
前置教训：本设计源自一次被用户叫停的投机式修补——券形按斜拍照片测了三次改了三次（半圆→尖拱→回滚），构件参数全部来自 GPT 聊天建议且无溯源，验收靠 GPT 凭直觉打分逐轮补丁。

## 0. 目标与非目标

**目标**：把 e30_shikongqiao_video/3d 的十七孔桥模型做到**构件级精细**，每个尺寸有据可查或明确标注为工作值，每条验收判据可证伪。

**非目标**：
- 不做照片级逐石风化/青苔/锈斑
- 不做 544 只狮子逐只不同（用 3-5 种母题布料）
- 不做金光穿洞等特定时刻的光影复现（用户明确：先不管金光，先把桥做最好）
- 不换渲染器/不换建模工具（沿用 Blender + Cycles + 现有脚本链）

## 1. 事实层 `3d/facts.py`（单一来源）

每条尺寸一行：`名 = 值  # [来源等级] 具体出处`。

来源四级，优先级从高到低：
1. `[测绘]` 文物测绘图、颐和园官方/文保档案公开数字
2. `[文献]` 学术论文、地方志、专著
3. `[实拍]` 照片——**只允许从近正面（正视偏角 <15°）照片提取"形"（券形、栏板纹样）；禁止从任何斜拍照片提取数值比例**。多源冲突不取区间值，采用权威口径并记差异（QA v2/E9 纪律）
4. `[工作值]` 查无实据的建模工作值，必须写明"假定依据"

**禁令**：
- GPT 聊天记录不算来源；GPT 给的数字一律进"待核清单"
- bridge_geom2.py / build_scene2.py 禁止出现字面尺寸数字，一律 `from facts import`
- 斜拍照片禁止用于数值测量（本设计的直接教训）

研究轮（P0）必须核实的存疑清单（初始）：
- 中央孔净跨：现用 8.50m [GPT冻结]，存疑，需 [测绘]/[文献] 核实
- 全部 17 孔跨序表（现 4.50/4.90/5.40/5.90/6.40/6.90/7.40/8.00/8.50 对称）
- 桥长 150m、桥面宽（现 6.56m 上宽）
- 栏板/望柱/地袱形制与尺寸（现值来自 GPT 建议）
- 望柱 128 根、柱头狮 544 只的口径
- 桥头异兽 4 只的规格（现 1.12m 高 [GPT建议]）
- 起拱线高度、墩厚、券圈宽度

产出：`facts.py` + `3d/refs/FACTS.md`（人读版，逐条来源）。

## 2. 几何层

- `bridge_geom2.py`：纯几何计算（跨序、券形、收分、deck_z），全部取数自 facts
- `build_scene2.py`：构件纯函数化，接口先冻结：
  `build_body_bm(f)`, `build_voussoir_bm(f)`, `build_impost_bm(f)`, `build_railing_bm(f)`, `build_lions_bm(f, spots)`, `build_beasts_bm(f)`, `build_cornice_bm(f)`, `build_plinth_bm(f)`, `build_causeway_bm(f)`
- 狮子：3-5 种母题（蹲坐/回首/抚幼/戏珠/站立），随机布料但种子固定（可复现）
- 接口冻结后构件才允许并行开发

## 3. 判据层 `3d/qa_bridge.py`（QA v2 纪律移植）

- **L1 事实自洽**（纯数据）：17 孔；跨序对称；券顶 ≤ 桥面−0.3m；起拱线 < 桥面；宽高比=0.50±0.01（半圆券）；facts 每条必有来源标注
- **L2 几何断言**（开 blend 查顶点）：构件对象存在且命名正确；望柱数=128±0；异兽=4；狮子实例数=544（母题布料不影响计数）；法线朝向（券洞内壁指向洞心，负控制：翻转一批必须 fail）；券石不入任何净空（现成硬约束保留）
- **L3 渲染比对**：正交立面（ortho.py 2200px）与参考图配准后边缘/构件位置叠加；偏差阈值以命名常量写入判据代码，P4 阶段用配准残差标定并注明依据；closeup 机位与实拍裁切并排人工核对项
- **负控制纪律**：每条判据落地时先写"故意破坏"用例（改错数据/翻转法线/挪走构件），破坏必须被抓，否则该判据无效
- 语义沿用：只有 `fail` 阻塞；`skip`=未执行，不算通过；判据未跑的构件不许报"完成"

## 4. 环境层（桥全绿后锁定）

- 一次性标定：PREETHAM 晴空、太阳 WNW 侧掠、水面、接岸长堤、5 机位
- 渲染契约（锁死）：`ortho 正立面 2200px`、`hero`、`arch 近景`、`rail 特写`、`lion 特写`
- 环境改动禁止触碰桥几何/判据文件；反之亦然

## 5. 终审

1. 程序判据全绿（自动）
2. **GPT 初审一轮**：必须逐条引用随附实拍图给出差异清单，禁止凭直觉泛评；输出到 `3d/refs/gpt_final_audit.txt`
3. **批判过滤**：GPT 每条意见必须经我核实——对 facts 来源、对 L1-L3 判据、对实拍图重测；核实通过才落改，核实不了标 `待证` 不改；被否决的意见记录否决理由（写入 `3d/refs/audit_disposition.md`）
4. **用户终验**：并排对照图 + 判据报告提交，用户拍板

## 6. 执行方式

- writing-plans 出实施计划后，按 subagent-driven 执行（同 QA v2 流程），ledger 用 `.superpowers/sdd/progress.md` 模式
- P3/M3 构件并行：接口冻结后并行 3-4 个 agent（共享 facts.py 只读）
- Python 3.9.6：禁 `X | None`、禁 `match`；中文提交信息 `<type>(<scope>): <摘要>`

## 7. 阶段与闸门（本体先行）

**结构原则**：桥体本体（17 券 + 墩 + 桥面 + 券圈 + 起拱线石）先建完、冻结，附属构件（栏板/望柱/狮子/异兽）不得在冻结前动工——教训：本事故中异兽/栏板/地形都建在券形未定型的桥体上，全部返工。构件遵循与本体相同的"先事实、再判据、再动工"循环。

| 阶段 | 内容 | 闸门 |
|---|---|---|
| M0 本体研究 | 只核实本体尺寸：跨序、券形、桥长、桥宽、墩厚、起拱线、券圈宽 → facts.py 本体节 | 本体每条数字带来源等级；未决项标 `[工作值]` 列出 |
| M1 本体判据 | qa_bridge.py 中本体相关 L1+L2 + 破坏用例 | 每条判据的破坏必须被抓 |
| M2 本体重建 | body/voussoir/impost 函数化重建 | 本体判据全绿；grep 无字面尺寸 |
| **M2.5 本体冻结闸门** | 正交立面与参考图配准比对 + 5 机位素颜出图 + **用户目验** | **用户点头后 facts.py 本体节锁死**；此后改本体必须走变更记录（`3d/refs/body_changelog.md`）并重跑本体判据 |
| M3 附属构件 | 逐构件：研究事实→判据→构建（栏板/望柱/狮子 5 母题/异兽；接口冻结后并行） | 构件判据全绿 + closeup 机位人工核 |
| M4 渲染契约 | 5 机位标定 + 正交立面配准比对（阈值命名常量） | L3 偏差 ≤ 阈 |
| M5 环境锁定 | 天空/水/堤定稿 | 5 机位出图，全部判据仍绿 |
| M6 终审 | GPT 初审（强制引实拍）→ 批判过滤 → 用户终验 | 用户拍板 |
