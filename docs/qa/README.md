**L4-d 引文一致性**（2026-10-02 补，E12/E13 两条实证盲区）：
- 计数自洽（快档即跑，纯口播文本）：口播「N个字」与紧邻引文实长矛盾 → `fail QUOTE_COUNT_MISMATCH`。校准案例：E12 p6「震钧写下五个字：今已毁尽」——实为四字，画面同秒可证伪，原七层全放行，靠人工反向走查才抓到。两种口播格式都覆盖：括号引文（「今已毁尽」+ 前后 12 字窗口找计数词）与冒号裸引文（`写下四个字：今已毁尽`，E12 实测格式，引文截到首个句读防吞后续分句）。
- 上屏核验（仅 `--ocr`）：口播引文（≥3 实义字，繁简归一双侧）在该页 OCR 文本找不到 → `warn QUOTE_NOT_ON_SCREEN`（OCR 漏读无法排除，诚实降级不阻塞）。
- OCR 参数基线 `qa_v2/frames.OCR_INIT_PARAMS` 常量化 + 防漂移测试：E13 反向走查 V3/V4 假警报的精确根因是审计脚本自配 PaddleOCR 参数（doc_ori 分类器把水彩板面判倒置后先旋转整图）。任何脚本需要 OCR 必须复用该常量或 `load_ocr()`。

## 为什么重做 QA

旧 `qa_all.py` 的判据是「槽位矩形内深色墨像素 > 40」。出过一次严重事故：

**它忘了做 plate→canvas 坐标换算**，拿 1672×941 的板面坐标直接切 1920×1080 的渲染帧。E11 P5 那一页它采到的是**插画上的香炉和木架**（墨像素 32062），真文字只有 2229 —— 94% 在测插画。于是「8/8 通过」是**假的**。

更根本的问题：**旧 QA 无法证明它的判据不是恒真的**。负控制实验显示，随便挑一个视觉上的「空白区」，实测 583 墨像素判为通过。该判据在插画上恒真。

## 核心设计：每条判据都有负控制

`assert_negative_control` 把每个槽位平移到**与所有真槽及自身原矩形都不相交**的空白处，断言检测器报「无文本」。若平移后仍判有文本 → 判据恒真 → `NEGATIVE_CONTROL_FAIL`（fail 级）。

平移落点用**自适应搜索**（四向 + 尺寸外推 + 对角 + 网格回退），`text_at` 的容差在负控制路径上**置 0**。无法构造负控制的槽（密集表格）记入 `untestable` 并跳过，不误判 fail。

## 实现过程中发现并修掉的问题

按发现顺序，每条都是真实数据上暴露的：

### 1. 负控制平移结构性假阳性（Critical）

初版固定平移 `x+300`。实测 **59 个槽平移后仍命中**（每页 2/2/39/2/2/3/5/3）——因为 `title` 宽 917、`sub` 宽 836，平移 300 后矩形仍罩住自身文字，而 `text_at` 还有 25px 容差。

后果：`--full` 8 页全报 fail，真恒真判据淹没在假阳性里失去区分度。

修法见上。

### 2. L4-a 两侧归一口径不对称（Critical）

```python
want = set(extract_numbers(item.text))                  # 原文，不归一
got  = set(extract_numbers(normalize_punct(got_raw)))   # 读回，先归一  ← 不对称
```

`'1799 → 1800 → 1801'` 在 `want` 侧是 `{1799,1800,1801}`，在 `got` 侧先被 `normalize_punct` 剥成 `'179918001801'` 再抽数字 → `{179918001801}`。**读回完全正确也报 mismatch**（E11 P7）。

违反 spec §5.2 明文的「两侧用同一函数，保证可比」。已改为同口径。

### 3. L4-c 判据问错了问题（19 条假阳性）

原假设：「画面上每个数字，口播必须逐个念出来」。**这个假设在真实数据上不成立**：

- P3 口播只念方位（「镶黄旗在树村西边」），**压根不念 24 个房数**
- P5 口播念「万历二十八年」而**不念 `1600`**（画面括号里是给现代读者的公历换算）

19 条 fail 全属此类——不是两边矛盾，是「画面补了口播不需要念的视觉信息」。

重新设计为**分类交叉**：
- 叙事槽位（title / timeline / note）严格核验——画面写 `1350` 而口播念 `1250` 立即报警
- 表格槽位走**动态竞争检测**——口播若念了同量级数字而表格填了别的，判定为事实冲突
- 纯视觉明细表豁免

### 4. OCR 数字粘连（6 条）

P3 表格最后一行（镶白旗）每格含**大/小两行数字**。OCR 把上下两行读成一行：`[39,26]`→`3926`、`[1167,315]`→`1167315`。横向也会粘连：`[65]`→`6539`。

修法用 **Decomposition DFS 拼块重构**——只有当读回数字能被「该页合法数字**精确无缝**拼回」才判粘连。关键边界：

| 场景 | 读回 | 判定 |
|---|---|---|
| `1485` → `1486` | `1486` | **fail**（C2 核心价值保留） |
| `1485` → `14850` | `14850` | **fail**（尾随 `0` 拼不出合法拼块） |
| `1485` → `14851167` | `14851167` | 粘连（=`1485`+`1167`，均为本页合法值） |

**没有用「是子串就放过」那种粗判据**——那会让真错值漏掉。

### 5. L3 负控制的两个实现 bug

- `run.py` 写 `if missed:` 没区分 `not_caught` 与 `untestable` → 无法构造负控制的槽被误报 fail
- 正反向置信判定不对称：L3 正向过滤了 `<0.80` 的低置信噪点，负控制路径没过滤 → P4 插画上一个置信 0.109 的篆字噪点被当成「判据恒真」

### 6. 繁简噪声（2 条）

OCR 把「正黄旗」读成「正**黃**旗」。`verify_subtitles_asr.py` 早有一张 `TRAD` 表，QA 的 `normalize.py` 没移植。已补齐并在归一函数里统一处理（**两侧都过**，不特例化）。

## 已知限制（诚实记录）

1. **快档不含 L3**。快档跑 L1/L2/L5/L6（纯数据 + 无 OCR 渲染检查），L3 与 L4 收口在 `--ocr` 档。理由：L3 的价值在于「该槽该有的 OCR 文本」这个精确判据，退化成「有没有墨」就退回旧 QA 的老路。**代码与 spec §5.1 已同步说明这个取舍。**

2. **繁简表永远不完整**。一张表覆盖不了所有汉字。E12 若出现新繁简字需追加。表在 `qa_v2/normalize.py`，扩充成本低。

3. **OCR 缓存不随内容失效**。改了文案重渲后**必须**手动清 `/tmp/qa_cache/<集>_*.json`，否则读到旧结果造成假阴性。

4. **L4-c 的卷号启发式是粗的**。`_is_volume_ref(n) = 1<=n<=200` 会把房数（65）、人数（375）也当卷号排除。已在 docstring 明说。

5. **口播语义只有部分覆盖**。L4-d 抓「计数词 vs 引文实长」与「引文是否上屏」两类可机器判定的错误；口播其余语义（表述矛盾、评价失当）仍需反向走查/人工终审。E12 p6 事故后补的判据，覆盖面以实测格式为准。

6. **密集表格页的 OCR 粘连**依赖「该页合法数字集合」做重构。若某页的粘连数字恰好都是合法值，会误判为粘连而放过。概率低但存在。
