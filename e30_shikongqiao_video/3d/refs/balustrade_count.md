# 望柱/栏板计数口径裁决：124 vs 128

- 日期：2026-10-05　|　执行：BalustradeCount agent（todo C phase 登记）
- 性质：纯研究，零代码改动，不 commit。
- 结论速览：**建模与叙述口径维持 128（NPOST=63/侧不变）；124 登记为并存口径。两数均无测绘/档案级出处，且均与本次实拍可数的"桥面段望柱格网"（≈88–104 根总量）对不上——差异大概率来自"是否计入八字翼墙/桥端段"的口径差或民间增殖，现有公开证据无法裁决，须文保档案或正射俯拍。**
- ⚠️ 连带勘误：`body_changelog.md`（2026-10-04 M3-2 复核节）称"若改用 124 根，544 无法这样分配"——**该论据为假**（见 §6.3），128 的现行选择理由需改挂到来源流通度上。

### 3.3 已识别并排除的四类计数陷阱（后续复数者必读）

1. **双栏交错**：低角度照片里南北两栏的望柱在画面上交错出"半柱距"假节奏（65px 实为 2×32.5 交错）。判据：真柱必须连着自身的栏板（柱间一块双格栏板）；`x6_east.png` 为无遮挡金标准。
2. **半周期谐波**：自相关会锁到 ≈柱距/2 的栏板格格点周期（37/73px 假峰），不能作为柱距。
3. **人群遮挡**：游客头部恰好吞掉 1.0–1.2 m 高的柱头狮（正如 `fine_crest.png` 中段），漏数 ~1/3 柱——只在人群背后栏板**连续可见**处计数。
4. **透视压缩**：端部数跨内柱距 2–3 倍速变，任何"远端直除"都会错；必须逐跨配本跨柱距。

### 3.4 数照片结论

- 桥面段（两桥头转角柱之间）格网 ≈**88–100 根**（两侧合计），柱距折算见 §4.3。
- **任一自洽读法都到不了 124/128**；缺额不是漏数（无遮挡段栏板连续性可证），而是**口径差**：公开数字几乎必然把两端的八字翼墙挂落栏板、转角柱与（可能的）桥头引桥段一并计入，或属转抄增殖——照片上翼墙段全部被树冠/兽像/人群遮挡或过小，**无法补数**。

## 4. 与现有 NPOST=63 的关系及连锁算式

### 4.1 裁决：**维持 128（NPOST=63/侧），124 登记为并存口径**

理由（按权重）：

1. **两候选都无测绘/档案级出处**（§1），差异仅 2 根/侧；本次照片证据又表明两者都非"纯桥面段实数"，在两者间二选一会制造来源不支持的虚假精度——**裁决应当保守**。
2. **128 是流通最广、带官方媒体载体的口径**（S3 京报网＝北京日报报业，S4/S5/S6 同口径矩阵）；124 的唯一具名出处是文学副刊散文（S7），按来源等级纪律不能反过来压过官媒流通口径。
3. 现模型几何柱距 2.381 m 与照片折算柱距 2.4–2.5 m（§4.3 档锚）偏差 ≤5%，在成片拍摄距离下单柱不可分辨（栏杆带 <40px），**改 61/侧无可见收益**。
4. 叙事安全：无论 124/128 都不得以"测绘=128根"措辞上屏（同"544 只石狮"禁令，见 §6.2）。

### 4.2 若未来证据（文保档案/正射俯拍）支持改判 124，连锁算式

```text
NPOST_side : 63 → 61
柱距       : BRIDGE_LEN/NPOST = 150/63 = 2.381 m → 150/61 = 2.459 m   (Δ +0.078 m, +3.3%)
栏板段/侧  : 63 → 61（柱间满铺，段数 = 柱数−1，端柱规则不变）
狮位分配   : 每侧 272 狮 = 5a + 4b, a + b = 61（a=五狮柱, b=四狮柱）
             代入: 5a + 4(61−a) = 244 + a = 272 → a = 28, b = 33
             验算: 28×5 + 33×4 = 140 + 132 = 272 ✔
             ⇒ 28 根五狮柱 + 33 根四狮柱（每侧）——分配存在且唯一（对 124 口径）
```
> 上式同时证明：**"124 无法分配 544"的旧论据为假**——`5a+4b=272, a+b=61` 有整数解（a=28, b=33）。body_changelog 该句须按 §6.3 修订。同理，128 口径下的 16×5+48×4 也只是 `5a+4b=272, a+b=64` 的一个普通解（272=244+a → a=28 同样成立），并不构成 128 特有的"内部一致性依据"。

### 4.3 若按本次实拍口径（待档案验证后再议，不立即执行）

```text
桥面段柱距（跨长档锚）: 柱距 ≈ Σ(跨长+墩顶墙)/总格 ≈ 2.4–2.5 m
桥面段柱数/侧        : ≈ 44–50（格网积分，17 开间 × 2~3.4 格/开间）
若建模改为桥面段实数 : NPOST_side ≈ 47 → 柱距 = RAIL_RUN/NPOST，
                       RAIL_RUN = Σfacts.SPANS + 16×墩顶墙厚 ≈ 124 m（跨长梯采用二手梯，须先升档）
栏板段/侧            : NPOST_side − 1
```
**尺度警告**：绝对米制折算依赖二手跨长梯（净跨4.60~8.50 m，吴齐正），跨梯未升档前，照片只能给出"格数/开间"这类无量纲比，柱距米数置信度 ±10%。

### 4.4 现状不变式（零改动确认）

- `NPOST=63` 不动 → 柱距 2.381 m、栏板 63 段/侧、渲染网格不变；
- FACTS.md §114 冻结的是**间距算式**（`BRIDGE_LEN/63`），柱数口径本就标注"不作计量事实"——维持；
- `test_freeze_manifest.py:234` 该参数 `locked=False`，本次裁决不触发冻结重跑。
